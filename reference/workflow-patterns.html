Workflow patterns and the ladder

From Lesson 1. Source: Anthropic, Building effective AI agents.

The one question

Who chooses the next step: your code (workflow) or the model (agent)?

The ladder: start at the bottom

  1. 3. Agent flexible, costly
    Model loops: tool call, observe, decide. Needs ground truth each step and a stopping condition.
  2. 2. Workflow predictable
    Your code wires several LLM calls together. Five patterns below.
  3. 1. Augmented LLM call cheapest
    One call plus retrieval, tools, memory.

Move up only when measured results on the lower rung fall short.

Five workflow patterns

PatternShapeUse when
Prompt chainingA → (gate) → B → CFixed sequential subtasks; accuracy over speed
Routingclassify → one of several handlersDistinct categories; cheap-vs-capable model split
Parallelizationfan out (sectioning or voting) → merge in codeSpeed, or multiple perspectives for confidence
Orchestrator-workersmodel plans subtasks at runtime → workers → synthesizeSubtasks unpredictable in advance
Evaluator-optimizergenerate → critique → repeatClear criteria; feedback measurably helps

Easy confusions

  • Parallelization vs orchestrator-workers: predefined subtasks vs subtasks the model decides at runtime.
  • Many steps ≠ agent: a long chain your code controls is still a workflow.
  • Frameworks: start with direct API calls; abstractions can hide prompts and responses.

Agent loop sketch

messages = [user_task]
for step in range(MAX_STEPS):
    reply = llm(messages, tools=TOOLS)
    if reply.is_final:
        return reply.text
    result = run_tool(reply.tool_call)
    messages += [reply, result]
